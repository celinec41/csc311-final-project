\subsubsection*{(e) Limitations}

One limitation is that the response matrix contains many missing entries. Therefore, the distance between two students or questions may be calculated from only a small amount of shared information and may not reflect true similarity.

A second limitation is that new students or questions have very little response data, making it difficult to identify reliable neighbours.

KNN also does not directly model student ability or question difficulty, and its computational cost increases as the number of students and questions grows.

\subsection*{2. Item Response Theory}
 
\subsubsection*{(a) Derivation}
 
Let $C \in \{0,1\}^{N \times M}$ denote the sparse matrix of $N$ students and $M$ questions, observed only on the index set $O$. The probability that student $i$ answers question $j$ correctly is
\[
p(c_{ij} = 1 \mid \theta_i, \beta_j) = \sigma(\theta_i - \beta_j) = \frac{\exp(\theta_i - \beta_j)}{1 + \exp(\theta_i - \beta_j)}.
\]
 
Assuming independence across observed entries, the log-likelihood is
\[
\log p(C \mid \theta, \beta) = \sum_{(i,j) \in O} \Big[ c_{ij}(\theta_i - \beta_j) - \log\big(1 + \exp(\theta_i - \beta_j)\big) \Big].
\]
 
Taking derivatives:
\[
\frac{\partial \log p(C\mid\theta,\beta)}{\partial \theta_i} = \sum_{j : (i,j) \in O} \Big[ c_{ij} - \sigma(\theta_i - \beta_j) \Big],
\]
\[
\frac{\partial \log p(C\mid\theta,\beta)}{\partial \beta_j} = -\sum_{i : (i,j) \in O} \Big[ c_{ij} - \sigma(\theta_i - \beta_j) \Big].
\]

\subsection*{3. Matrix Factorization / Neural Network}
\begin{questionbox}
In this problem, you will implement neural networks to predict students' correctness on a
diagnostic question. Specifically, you will design an autoencoder model. Given a user
$\mathbf{v} \in \mathbb{R}^{N_{\text{questions}}}$ from a set of users $\mathcal{S}$, our
objective is:
\[
\min_{\theta} \sum_{\mathbf{v} \in \mathcal{S}} \| \mathbf{v} - f(\mathbf{v}; \theta) \|_2^2,
\]
where $f$ is the reconstruction of the input $\mathbf{v}$. The network computes the following
function:
\[
f(\mathbf{v}; \theta) = h\big(\mathbf{W}^{(2)} g(\mathbf{W}^{(1)} \mathbf{v} + \mathbf{b}^{(1)}) + \mathbf{b}^{(2)}\big) \in \mathbb{R}^{N_{\text{questions}}}
\]
for some activation functions $h$ and $g$. In this question, you will be using sigmoid
activation functions for both. Here, $\mathbf{W}^{(1)} \in \mathbb{R}^{k \times N_{\text{questions}}}$
and $\mathbf{W}^{(2)} \in \mathbb{R}^{N_{\text{questions}} \times k}$, where $k \in \mathbb{N}$
is the latent dimension. We provide the starter code written in \texttt{PyTorch} at
\texttt{neural\_network.py}.
\end{questionbox}

\subsubsection*{(a)}
\begin{questionbox}
Describe at least three differences between ALS and neural networks.
\end{questionbox}
\solution

There are several key differences between ALS and neural networks:
\begin{itemize}
    \item \textbf{Model expressiveness.} ALS assumes the prediction is simply the dot product of two vectors, $C_{nm} \approx \mathbf{u}_n^\top \mathbf{z}_m$, which is a bilinear model and can only capture linear relationships. The neural network introduced the sigmoid non-linearity between the two weight layers, so it can model more complex, non-linear relationships between student ability and question difficulty.

    \item \textbf{Parameter structure.} In matrix factorization trained via ALS, each student has its own latent vector $\mathbf{u}_n$ and each question has its own latent vector $\mathbf{z}_m$; these parameters are learned directly,
    and their number grows linearly with the number of students and questions. In the neural network, all students share the same set of weights $\mathbf{W}^{(1)}$, $\mathbf{W}^{(2)}$  and biases $\mathbf{b}^{(1)}$, $\mathbf{b}^{(2)}$. A student's ``representation'' is not a freely learned parameter but is instead computed by passing that student's raw answer vector through the network. Consequently, the number of parameters depends only on the number of questions and the chosen latent dimension, and does not grow with the number of students.

    \item \textbf{Optimization procedure.}
    ALS alternates between fixing $\mathbf{Z}$ and updating $\mathbf{U}$, then fixing $\mathbf{U}$ and updating $\mathbf{Z}$, repeating this process even when implemented
    with SGD. The neural network is trained end-to-end: all parameters ($\mathbf{W}^{(1)}$, $\mathbf{W}^{(2)}$, $\mathbf{b}^{(1)}$, $\mathbf{b}^{(2)}$) are updated jointly in a single backward pass, with no alternating step.

    \item \textbf{Gradient computation.}
    In ALS, we must manually derive the gradient of the loss with respect to $\mathbf{u}_n$ and $\mathbf{z}_m$ and hand-code the update rule. In the neural network, gradients are computed automatically via PyTorch's autograd. The only thing we need to define is the forward pass, and backpropagation is handled by the framework.
\end{itemize}

Implement a class \texttt{AutoEncoder} that performs a forward pass of the autoencoder

\solution

The forward function defines a single pass of the autoencoder: it takes a student's answer vector as input, compresses it, and then reconstructs it back to its original size.

\textbf{Step 1 — Encoding.} self.g(inputs) applies a linear transformation that maps the 1774-dimensional input down to a k-dimensional vector. Wrapping it with torch.sigmoid squashes every value into the range [0, 1], producing the hidden representation hidden. This step compresses the student's full answer pattern into a smaller latent representation of size k.

\textbf{Step 2 — Decoding.} self.h(hidden) applies a second linear transformation that maps the k-dimensional hidden vector back up to 1774 dimensions. Wrapping it with torch.sigmoid again squashes each output into [0, 1], giving the final output out which is interpreted as the model's predicted probability that the student answers the corresponding question correctly.

\section*{Part B}
 
\subsection*{1. Formal Description}

\textbf{Motivation.} In Part A, both user-based and item-based KNN impute a student-question pair $(i,j)$ using only the $k$ training rows (or columns) nearest to row $i$ (or column $j$) under a NaN-aware Euclidean distance. When a student or question has very few observed entries, the neighbourhood used to compute this distance is small and the resulting distance estimates -- and hence the imputed probability -- are noisy: KNN has low bias but high variance in the sparse regions of $C$. A natural way to reduce this variance is to blend the KNN estimate with a much lower-variance, higher-bias estimate that ignores neighbour structure entirely and simply averages all training observations for that student or question. We formalize this blend below.

\textbf{Base predictors.} Let $C \in \{0,1,\mathrm{NaN}\}^{N \times M}$ be the training response matrix ($N=542$ students, $M=1774$ questions) and let $O$ denote the set of observed $(i,j)$ pairs. Let $\hat{c}^{\text{user}}_{ij}, \hat{c}^{\text{item}}_{ij} \in [0,1]$ be the probabilities produced by the Part A user-based ($k=11$) and item-based ($k=21$) KNN imputers, respectively (Section 4.1). Define two correctness priors directly from the training data:
\[
\pi^{q}_j = \frac{\sum_{i : (i,j) \in O} c_{ij}}{|\{i : (i,j) \in O\}|}, \qquad
\pi^{s}_i = \frac{\sum_{j : (i,j) \in O} c_{ij}}{|\{j : (i,j) \in O\}|},
\]
the empirical correctness rate of question $j$ and of student $i$ over the training set, each falling back to the global training correctness rate $\bar{c} = \frac{1}{|O|}\sum_{(i,j)\in O} c_{ij}$ if the corresponding row or column has no observations.

\textbf{Hybrid model.} Given weights $\alpha, \beta, \gamma \in [0,1]$, define
\[
p^{\text{knn}}_{ij}(\alpha) = \alpha\, \hat{c}^{\text{user}}_{ij} + (1-\alpha)\, \hat{c}^{\text{item}}_{ij}, \qquad
p^{\text{prior}}_{ij}(\beta) = \beta\, \pi^{q}_j + (1-\beta)\, \pi^{s}_i,
\]
\[
p_{ij}(\alpha,\beta,\gamma) = \gamma\, p^{\text{knn}}_{ij}(\alpha) + (1-\gamma)\, p^{\text{prior}}_{ij}(\beta),
\]
and predict $\hat{c}_{ij} = \mathbb{1}[\,p_{ij}(\alpha,\beta,\gamma) \geq \tau\,]$ for a threshold $\tau \in [0,1]$. This is a strict generalization of Part A: setting $\gamma=1,\alpha=1$ recovers user-based KNN alone, and $\gamma=1,\alpha=0$ recovers item-based KNN alone.

\textbf{Hyperparameter selection.} The hyperparameters $(\alpha,\beta,\gamma,\tau)$, together with the choice of $k$ and weighting scheme (uniform or inverse-distance) for the two base KNN predictors, are selected by grid search to maximize accuracy on the validation set, as summarized in Algorithm~\ref{alg:tuning}. The test set is never used for selection.

\begin{algorithm}[H]
\caption{Validation-selected hybrid tuning}
\label{alg:tuning}
\begin{algorithmic}[1]
\STATE Fit every candidate user-/item-KNN configuration (Part A baseline and distance-weighted, $k \in \{5,\dots,50\}$) on the training matrix $C$; cache their predictions on the validation set.
\STATE Compute $\pi^{q}_j$ and $\pi^{s}_i$ from $C$; index them onto the validation pairs.
\STATE $\text{best\_acc} \leftarrow -\infty$
\FOR{each pair of user/item KNN configurations}
    \FOR{$\alpha, \gamma, \beta, \tau$ in their respective grids}
        \STATE Compute $p_{ij}(\alpha,\beta,\gamma)$ and $\hat{c}_{ij}$ for all validation pairs
        \STATE $\text{acc} \leftarrow$ validation accuracy of $\hat{c}$
        \IF{$\text{acc} > \text{best\_acc}$}
            \STATE $\text{best\_acc} \leftarrow \text{acc}$; store $(\text{configs}, \alpha,\beta,\gamma,\tau)$
        \ENDIF
    \ENDFOR
\ENDFOR
\STATE Refit the two selected KNN configurations, evaluate the stored hyperparameters once on the test set.
\end{algorithmic}
\end{algorithm}

\textbf{Why this should help.} The hybrid is a convex combination of a low-bias/high-variance predictor ($p^{\text{knn}}$) and a high-bias/low-variance predictor ($p^{\text{prior}}$). Whenever the two make partially independent errors, which we expect for sparse rows/columns, where KNN's neighbour-based estimate is unreliable but the prior's aggregate is not, the convex combination has strictly lower expected squared error than either endpoint for some interior $\gamma$, by the standard bias-variance decomposition of a weighted average. Because $\alpha,\beta,\gamma,\tau$ are chosen on a held-out validation set, this argument only predicts an improvement in expectation, not that our particular grid search finds the population-optimal weights; Section 3 tests this expectation directly, including which of the two priors actually drives the improvement.

The final hybrid improves test accuracy by roughly $2.3$ percentage
points over the stronger Part A baseline
(user KNN, $68.47\% \to 70.79\%$), and by about $1.2$ points over a
naive unweighted average of the two Part A models
($69.63\% \to 70.79\%$), confirming that the gain is not simply from
averaging two noisy predictors.

\subsubsection*{Disentangling the source of the improvement}

Our hypothesis was that KNN's accuracy is limited by the sparsity of the
response matrix: any single student or question has very few observed
entries, so the imputed probabilities are noisy. We expected two
changes to help: (i) tuning and combining the user- and item-based KNN
predictors, and (ii) backing off sparse predictions toward simple,
low-variance correctness priors (per-question and per-student averages).
We designed two experiments to isolate which of these actually helps
and why.

\textbf{Experiment 1 -- which prior helps?}

We compared adding only the question-difficulty prior, only the
student-ability prior, and both, to the 50--50 hybrid
(Table~\ref{tab:partb_results}). Both priors individually improve on
the plain hybrid: the question prior alone raises validation accuracy
from $70.41\%$ to $70.49\%$
($69.63\% \to 70.17\%$ test), and the student prior alone raises
validation accuracy further to $70.90\%$ ($70.03\%$ test). Combining
the two priors in equal proportion ($\beta=0.50$) outperforms either
alone, reaching $71.15\%$ validation and $70.79\%$ test accuracy, so
the selected configuration blends both priors rather than relying on a
single one.

This matches the underlying intuition that per-student and
per-question correctness rates each carry some independent signal
beyond what the KNN imputers capture, and mixing the two priors together
reduces variance further than either alone.

\textbf{Experiment 2 -- is the gain from the priors, or from a larger
search?}

We compared the independently tuned user- and item-based KNN models
with the hybrid models. The best tuned user KNN still achieves
$68.97\%$ validation accuracy and $68.47\%$ test accuracy, while the
best tuned item KNN still achieves $69.16\%$ validation accuracy and
$68.28\%$ test accuracy. These values are the same as the Part A
baselines.

In contrast, combining the two KNN predictors increases validation
accuracy to $70.41\%$, and adding both priors increases it further to
$71.15\%$. On the test set, the strongest individual Part A result is
$68.47\%$, the 50--50 hybrid reaches $69.63\%$, and the final hybrid
reaches $70.79\%$.

This suggests that the improvement is mainly attributable to combining
the priors and the two KNN prediction sources, rather than simply
searching over a larger set of KNN hyperparameters.

Figure~\ref{fig:partb_tuning} shows the validation sensitivity of the
final hybrid to $\beta$ (question- vs. student-prior weight) and to
$(\gamma,\tau)$ (KNN-vs-prior weight and classification threshold) at
the selected configuration. The selected
$(\gamma,\tau)=(0.70,0.55)$ lies at the edge of the searched grid.
Several nearby configurations achieve similar validation accuracies,
although the best result still occurs at the boundary of the search
range.

\begin{figure}[H]
    \centering
    \includegraphics[width=0.95\textwidth]{partb_knn_tuning.png}
    \caption{Validation accuracy as a function of the prior-blend
    weight $\beta$ (left), and as a function of the KNN-vs-prior weight
    $\gamma$ and threshold $\tau$ at the selected
    $\alpha=0.50$ and $\beta=0.50$ (right).}
    \label{fig:partb_tuning}
\end{figure}

The left panel shows that validation accuracy is highest at
$\beta=0.50$, meaning that the selected model gives equal weight to the
question prior and the student prior. Since
\[
p^{\text{prior}}_{ij}(\beta)
=
\beta\pi_j^q+(1-\beta)\pi_i^s,
\]
the selected value gives
\[
p^{\text{prior}}_{ij}
=
0.50\pi_j^q+0.50\pi_i^s.
\]

With $\alpha=0.50$ and $\beta=0.50$ fixed, the right panel shows that
the best searched combination is
\[
\gamma=0.70,
\qquad
\tau=0.55,
\]
which achieves $71.15\%$ validation accuracy.

The value $\alpha=0.50$ means that the KNN component gives equal weight
to the user-based and item-based KNN predictions:
\[
p^{\text{knn}}_{ij}
=
0.50\hat{c}^{\text{user}}_{ij}
+
0.50\hat{c}^{\text{item}}_{ij}.
\]

The value $\gamma=0.70$ means that the final probability uses $70\%$
weight from the KNN component and $30\%$ weight from the prior
component:
\[
p_{ij}
=
0.70p^{\text{knn}}_{ij}
+
0.30p^{\text{prior}}_{ij}.
\]

Therefore, after expanding all weights, the final probability gives
$35\%$ weight to user-based KNN, $35\%$ weight to item-based KNN,
$15\%$ weight to the question prior, and $15\%$ weight to the student
prior.

The threshold $\tau=0.55$ means that the model predicts a correct
response when
\[
p_{ij}\geq 0.55,
\]
and predicts an incorrect response otherwise. This threshold was
selected because it gave the highest validation accuracy among the
tested values.

Overall, the results support our hypothesis. Combining user- and
item-based KNN captures complementary similarity information, while the
student and question priors provide lower-variance information that
helps stabilize predictions in sparse regions of the response matrix.
The fact that the best $(\gamma,\tau)$ combination lies at the edge of
the searched grid suggests that a wider search over $\gamma$ and
$\tau$ could be explored in future work.


\subsection*{4. Limitations}

\textbf{Sparsity is only partially addressed.} The priors help because both students and questions have more observed entries on average than a single KNN neighbourhood does, but each prior is still just a single scalar per student or per question; for students or questions with very few responses, the prior itself falls back to the global average and provides little personalization. The approach would perform poorly for a genuinely cold-start student or question with zero training observations, since both the KNN imputers and the priors are undefined (or degenerate to the global mean) in that regime.

\textbf{Heuristic rather than principled combination.} Unlike IRT, which derives $p(c_{ij}=1)$ from an explicit probabilistic model with interpretable parameters, our hybrid combines KNN outputs and priors through hand-tuned linear weights ($\alpha,\gamma,\beta$) and a threshold ($\tau$) selected by brute-force grid search. The method offers no principled explanation of \emph{how much} weight each prior should get in general -- that answer is entirely dataset-dependent and would need to be re-tuned from scratch on a different dataset or a different student/question ratio.

\textbf{Sensitivity to hyperparameter search size and to the computing environment.} As Experiment 2 showed, a larger hyperparameter grid can increase validation accuracy while decreasing test accuracy, purely from the validation set (about 1500 rows) being too small to reliably rank a large number of candidate configurations. We also observed, while re-running our own code, that the selected $(\alpha,\beta,\gamma,\tau)$ combination is not perfectly stable across re-runs on different machines: two identical copies of the code produced slightly different selected hyperparameters (e.g. a different $\alpha$ or $\beta$), which we traced to small floating-point differences in the underlying nearest-neighbour distance computation across library/hardware versions changing which of several near-tied grid points is selected as the arg-max. This means our reported test accuracy is itself only a point estimate; a different validation split, or even a different machine, could plausibly select a different configuration with a couple of points' difference in test accuracy. A more robust extension would use cross-validation, a larger held-out set, or an explicit tie-breaking / stability check for the final hyperparameter selection instead of a single validation split.

\textbf{Unused structure.} We did not use \texttt{question\_meta.csv} or \texttt{student\_meta.csv}. A natural extension is a hierarchical prior, e.g., backing a sparse question's difficulty estimate off to its subject's average correctness rather than the global average, which could recover additional signal beyond the flat priors used here.

\textbf{Under-explored search range.} Our selected $(\gamma,\tau)$ sits at the edge of the range we searched, with validation accuracy still increasing toward that edge rather than peaking inside the grid. Our reported test accuracy is therefore likely a slight underestimate of what this hybrid approach can achieve; we chose not to widen the grid further in order to keep the comparison in Experiment 2 controlled, but a follow-up search over a wider $(\gamma,\tau)$ range (and possibly finer steps) is a low-effort way to likely improve on our numbers.
